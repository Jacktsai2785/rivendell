30 個 session 裡，真正有「多步驟工具鏈」可萃取的只有 5 個（code-review 系列）；其餘 25 個是單輪 prompt-in/text-out 的自動化管線輸出（新聞摘要、逐字稿摘要），沒有工具編排可言，不適合包裝成 skill。整體收穫偏薄。

## 二、觀察到的模式

1. **自動化管線輸出，非互動式協作**：podcast 摘要與台灣產業新聞摘要共 18 個 session，全是外部排程系統餵 prompt、拿到文字結果即結束，零工具呼叫。這代表這兩條線已經在 Claude Code 之外跑起來了（很可能是獨立腳本呼叫 API），不是「使用者在 Claude Code 裡重複做的操作」，故不適合做成 rivendell skill。
2. **collab-design / collab-review 子呼叫**：這些是既有 `collab-design`、`collab-review` skill 呼叫子 agent 時產生的內部 session，本身就是機制的一部分，不是新模式。
3. **同一個瀏覽器擴充套件被連續審查 5 次**：`tmp-collab-review-*-repo` 系列反覆審查同一組檔案（api.js、background.js、offscreen.js、popup.js），符合 Chrome MV3 架構（background + offscreen + popup + message passing）。這是唯一有「重複多步驟工具鏈」訊號的群組：Agent 扇出 → Read 原始碼 → Bash 查 git/diff → ToolSearch/WebSearch 查漏洞情資 → 產出 review。但底層機制（`/code-review xhigh`、refs/review/base|target 隔離）已經是既有成熟功能，真正可萃取的是「MV3 擴充套件特有的安全檢查重點」這個領域知識，而非流程本身。

## 三、Skill 候選清單

### 1. `mv3-extension-security-checklist` — Moderate

- **用途**：預載 Manifest V3 瀏覽器擴充套件常見風險點（background↔offscreen↔popup 的 message passing 來源驗證、CSP 設定、permissions 最小化、offscreen document 生命週期管理），在 `/code-review` 審查此類專案時直接注入檢查清單，避免每次重新發現同樣的問題類別。
- **觸發時機**：偵測到專案含 `manifest.json`（`manifest_version: 3`）+ `background.js`/`offscreen.js`/`popup.js` 組合，或使用者要求 review Chrome/Edge 擴充套件。
- **分類**：quality（審查類）
- **理由**：同一組檔案在短時間內被審查 5 次，代表這是進行中的專案，且每次都要重新建立 MV3 特定的風險模型；封裝成 checklist 可讓後續 review 更快聚焦，也能與既有 `security-review`、`engineering:code-review` 互補而非重複。
- **前提檢查**：確認 rivendell 內尚無此 skill —— 目前列表中 `quality/` 底下只有 de-slopify、github-repo-audit、large-file-refactor、protect-secrets、qa-auto/planner/testing，無 MV3 專用項目，可視為新建。

### 2. 台灣產業新聞每日摘要範本 — Weak（不建議現在做成 skill）

- **用途**：8 類產業新聞分類+摘要+高頻標題的固定格式。
- **理由不建議**：這 15 個 session 全部零工具呼叫，顯示背後已有獨立管線（排程抓新聞→組 prompt→呼叫模型）在 Claude Code 之外運作。做成 rivendell skill 不會被這條管線用到，除非使用者想把它改接到 `headless-agent`／`launchd-agent` 之類既有排程 skill 上——若有此需求應先問清楚，而非現在動手包。

### 3. Podcast 逐字稿摘要範本（中/英雙語）— Weak（同上，不建議）

- **理由**：與上一項同理，3 個 session 都是外部 podcast-transcriber 管線的輸出，無 Claude Code 內操作可萃取。
